## 1. 交付定义（周一「完成」长什么样）

评审对象能在 30–40 分钟内过完，并当场拍板「可以进入实现计划」。

| 交付物 | 合格标准 |
|---|---|
| PRD | 覆盖仓库/库区/库位/查询/流水；字段、校验、空态、权限、跨模块契约齐全；明确非目标 |
| 原型 | 主路径可点：建仓 → 建三类库区 → 建到列层 → 查询两种视角（含空态与有数示意）→ 流水列表；无盘库/退货/报损作业入口 |
| 契约一页纸 | 入出库实习生能按写账时点与库区约束开工，不反向改本模块口径 |
| 待决清单 | 仅剩规格未写死的补强项；已拍板项不再讨论 |

原型工具建议：Figma 或 MasterGo。本仓库只放规格与大纲，**不提交前端工程**。

## 4. 允许在周一拍板的待决项（规格未写死）

这些可以设计建议，但必须在评审里口头确认，**不要当成已经推翻或修改规格**：

| 编号 | 待决 | 建议默认 |
|---|---|---|
| Q1 | 库位是否需要独立编码字段 | 要；由五段生成，全局唯一，可复制 |
| Q2 | 仓库名称是否唯一 | 唯一 |
| Q3 | 库区类型能否修改 | 不能 |
| Q4 | 有库存库位能否改货架/列/层 | 不能改层级段；避免账记到「已改名的另一个位置」 |
| Q5 | 空库位能否删除 | 能；有库存或被未完成单据引用则不能 |
| Q6 | 新建仓库是否默认生成三类空库区 | 要；库位仍手建，避免自动造大量空位 |
| Q7 | 一期是否做按钮级权限 | 不做细权限也可；文档仍按运营维护、仓管查询来写主路径 |
| Q8 | 草稿采购是否计入在途 | 不计 |

已拍板、周一 **禁止** 重开的：系统独立、不建品、不回写可售、日常入库必须采购单、每仓一次期初、出库先预检后冻结、拣货才扣减、打包不改库存、推荐只走存储区。
