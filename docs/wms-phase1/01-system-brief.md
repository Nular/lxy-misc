# 微型仓 WMS 一期 · 系统信息梳理

日期：2026-08-19  
依据：已确认《微型仓 WMS 设计说明》  
原则：不推翻已拍板结论；本文只整理，不扩一期范围。

## 1. 系统是什么

独立微型仓 **执行系统**，配套跨境零售电商，与 C 端作业解耦。

- 商品主数据只读电商库；WMS **不建品**。
- 库存按库位记账：冻结、增减、履约状态流转。
- **不回写**电商可售（接口位置预留，一期不调用）。

订单路径：C 端导出 Excel → 运营在表内分 parcel → 导入 WMS。电话确认发生在导入之前，仓内不重复锁一次。

## 2. 一期三个一级模块（分工）

```text
库存管理（本侧负责，对外可称仓库管理模块）
├── 仓库管理（创建 / 列表 / 编辑 / 删除；名称、地址）
├── 库区与库位（收货区 / 存储区 / 报损区；货架-列-层）
├── 库存查询（Product 视角 / SKU 视角；锁定 / 未锁定 / 实物）
└── 库存流水（期初、采购入库、占用、扣减、解冻）

入库（实习生 A）
├── 采购单（做在入库模块内，不单独成一级）
├── 表单部分收货
├── Excel 批量收货（行上必须有采购单号）
└── 期初 Excel（每仓一次，无采购单号）

出库（实习生 B）
├── Excel 导入预检（不写库）
├── 按 SKU 推荐库位并确认冻结
├── 拣货确认扣减
└── 打包 / 发运（只改状态；可关单解冻）
```

说明：规格一级模块名是「库存管理」。本侧负责该一级模块；其中可独立先设计、不依赖入出库写账的是「仓库 / 库区 / 库位」主数据。库存查询与流水是同一模块的读侧，数字由入出库写入。

## 3. 已拍板约束（只摘与全系统相关的）

| 项 | 结论 |
|---|---|
| 库位精度 | 仓库 → 库区 → 货架 → 列 → 层 |
| 库区类型 | 收货区、存储区、报损区 |
| 实物口径 | 实物 = 已锁定 + 未锁定（可用） |
| 账面口径 | 账面库存 = 实物库存 + 在途库存 |
| 在途 | 来自采购未收，不记在库位账上 |
| 出库推荐 | 只使用存储区且 `available > 0` |
| 收货区 | 一期允许入库记到收货区；出库不从收货区推荐 |
| 报损区 | 一期只建档，不推荐、无报损作业 |
| 冻结 | 出库预检通过且确认导入后，按确认库位冻结 |
| 扣减 | 拣货确认；打包/发运只改单据状态 |
| 日常入库 | 必须有采购单 |
| 期初 | 每仓仅一次无采购单号批量导入 |
| 预检 | 出库、日常入库 Excel 均为全过才允许确认（无部分成功） |

## 4. 核心对象一览

| 对象 | 关键字段 | 一期要点 |
|---|---|---|
| 仓库 | 名称、地址 | 有库存或未完成采购/入出库单不可删 |
| 库区 | 隶属仓库，类型 | 三类必须能建 |
| 库位 | 仓库 + 库区 + 货架 + 列 + 层 | 全局唯一；库存记在库位 |
| 商品副本 | Product / SKU | 只读电商；可缓存；电商不可达则预检失败 |
| 库位库存 | on_hand / locked / available | available = on_hand − locked |
| 采购单 | 头+行；已收/未收 | 行不写库位；状态草稿→已确认→部分入库→已完成/已关闭 |
| 入库单 | 采购收货 / 期初 | 确认上架后实物↑、未锁定↑ |
| 出库单 | parcel、建议/确认库位 | 预检中→待确认库位→已占用→已拣货→已打包/已发运；可关闭解冻 |
| 库存流水 | 类型、关联单号、变更后三量 | 期初入库、采购入库、出库占用、出库扣减、取消解冻 |

对象类型预留（一期不实现入口）：入库可扩展退货/无单；流水可扩展盘盈盘亏报损移库。

## 5. 主链路（只记交接，不重画全图）

1. 电商建 Product/SKU → WMS 只读，不建品。
2. 运营维护仓库 / 库区 / 货架-列-层 → 库存查询可按库位看账。
3. 运营建采购单 → 记未收。
4. 到货：批量 Excel（须采购单号）或每仓一次期初；仓管可表单部分收。预检失败不写库。
5. 确认上架 → 实物↑未锁定↑；回写采购；写流水。
6. C 端导出订单 → 运营电话确认并分 parcel（可不写库位）。
7. 导入出库 → 预检不写库 → 推荐存储区现货 → 确认后冻结。
8. 拣货确认 → 已锁定↓实物↓。打包/发运只改状态。关单则解冻。

角色：电商后台建品与导出；运营建仓/采购/Excel/确认库位/关单；仓管部分收、上架、拣货、发运；WMS 预检、推荐、记账、流水。WMS 不回写可售。

## 6. 一期明确不做

盘库作业、退货作业界面、无采购单的日常入库（期初除外）、自动波次与拣货路径、报损作业、库存回写电商、部分成功导入。

盘库以后若做，放在库存管理模块；本期仓库管理 **不出现** 盘库、退货入口。

## 7. 对仓库管理设计的直接含义

- 先把「仓 → 区 → 货架-列-层」建对、唯一、可维护，入出库才有地方记账。
- 查询与流水是本模块页面，但写账权在入出库；本侧要先把 **读模型与契约** 写死，避免实习生各写一套数量口径。
- 报损区必须能建，但界面上不能做成报损作业。
- 验收时本模块至少独立可验：建仓、三类库区、库位到列层；查询两种视角与流水在入出库联调后验数字。
