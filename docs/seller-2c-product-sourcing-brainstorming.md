# Seller 后台 2C 店铺 — 选品中心（Product Sourcing）Brainstorming

> **产品**：KickBazar Seller 后台（2C 商家端）  
> **文档版本**：v0.5（Product Discovery 增加铺货 Tab：All / Published / Unpublished）  
> **目标市场**：孟加拉国（Bangladesh）  
> **背景**：App 端已有选品→下单→转账→铺货闭环；本期在 **Seller Web 后台** 补齐 2C 商家选品与采购能力  
> **方法**：Brainstorming（发散 → 归类 → 收敛）  
> **本期范围**：选品中心 + 立即购买 + 银行转账结算 + 转账凭证上传 + 采购订单 + 一键上架（**不含购物车**）

## 一、业务背景与角色

### 1.1 平台生态

```
┌─────────────────────────────────────────────────────────────────┐
│                        KickBazar 平台                            │
├──────────────┬──────────────────────┬───────────────────────────┤
│  自营店铺     │  自有货源              │  第三方入驻店铺              │
├──────────────┴──────────────────────┴───────────────────────────┤
│  2B 商铺（货源端）          ←── 选品 ──→    2C 商家（零售端）       │
│  · 商品供给                  下单/转账/铺货   · 面向消费者销售         │
│  · 确认收款（Web）                          · 此前主要在 App 操作     │
│  · 按订单发货                               · 本期扩展 Web 选品       │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 已有能力（App + 2B Web）

| 端 | 角色 | 已有能力 |
|----|------|---------|
| **App（2C 商家）** | 零售商家 | 注册登录、选品浏览、下单、转账、铺货上架 |
| **2B Web（货源方）** | 2B 账户 | 根据订单/转账信息 **确认收款**；确认后商家可 **一键上架**；2B 按订单 **发货** |
| **Seller Web（2C）** | 零售商家 | **本期新增**：选品中心、立即购买、银行转账结算、采购订单 |

### 1.3 本期核心问题

| 维度 | 描述 |
|------|------|
| **现状** | 2C 商家选品、采购主要在手机 App；PC 办公场景无法高效操作 |
| **目标** | 在 Seller 后台 2C 店铺增加 **选品中心**，Web 端完成「浏览 → 下单 → 转账 → 查单」 |
| **约束** | 暂不做购物车；支付以 **银行转账** 为主；商品来源限定 **2B 店铺** |
| **对齐** | 业务规则、订单状态、转账信息与 App / 2B 端保持一致 |

### 1.4 用户画像

| Persona | 特征 | 核心诉求 | 典型路径 |
|---------|------|---------|---------|
| **P1 小店主** | 孟加拉本地个体户，手机+偶尔用电脑 | 快速找货、少步骤下单 | 搜索 → 详情 → 立即购买 |
| **P2 铺货型商家** | 已有 2C 店铺，频繁补货 | 看哪些已铺货、哪些未铺货 | Tab「已发布/未发布」筛选 → 批量心理比对 |
| **P3 转账操作员** | 店员负责打款，老板负责选品 | 订单号清晰、收款账户可复制 | 下单成功页 → 复制 2B 账户信息 → 线下转账 |
| **P4 跟单员** | 关注发货进度 | 采购订单列表与详情状态准确 | 采购订单 → 详情看物流/收款状态 |

## 三、核心用户旅程

### 旅程 1：首次选品采购（主路径）

```
登录 Seller 2C 后台
  → 选品中心（默认 Tab：全部）
  → 浏览商品卡片 / 搜索关键词
  → 点击卡片 → 商品详情（橱窗型）
  → 立即购买 → 选择规格/数量（若有 SKU）
  → 结算页：确认金额、收货信息、支付方式=银行转账
  → 提交订单 → 下单成功页
  → 展示 2B 收款账户信息（户名、银行、账号、订单号、应付金额）
  → 商家线下转账 → **上传转账凭证**（成功页 / 订单详情）
  → 2B 在 2B 端确认收款
  → 2C 在采购订单详情看到「已确认收款」→ 等待发货 → 收货
  → **一键上架**至 2C 店铺（严格依赖 2B 已确认收款）
```

### 旅程 2：区分已铺货 / 未铺货

```
Purchase Orders List → Tab「Published」→ 查看已铺货 SPU 的采购订单
Purchase Orders List → Tab「Unpublished」→ 查看未铺货 SPU 的采购订单 → 详情一键上架
```

### 旅程 3：跟单与复购

```
选品中心 → 采购订单 → 筛选「待转账/待确认收款」
  → 订单详情 → 再次查看转账信息
待发货/已发货 → 查看物流（若 2B 回传）
  → 详情页「再次购买」→ 跳转商品详情（⏳ 可 P1）
```

## 四、分模块 Brainstorming 详述

---

### 模块 A：选品中心 — 商品列表

**定位**：2B 店铺货源的浏览与筛选入口。

#### A1. 业务规则（已确认）

| 规则 ID | 规则 | 优先级 |
|---------|------|--------|
| BR-01 | 商品列表数据源 = **绑定单一 2B 店铺** 的可售商品（非多 2B 混合） | P0 |
| BR-02 | 铺货状态 Tab：**Product Discovery** 提供全部 / 已发布 / 未发布 / 部分发布（**SPU 维度**）；**Purchase Orders List** 提供全部 / 已发布 / 未发布；订单 Detail 无 Tab | P0 |
| BR-03 | **铺货按 SPU 维度**；**采购按 SKU 维度**（可分 SKU 下单） | P0 |
| BR-04 | 「已发布」= 该 **SPU** 已在当前 2C 店铺铺货上架 | P0 |
| BR-05 | 「未发布」= 该 **SPU** 尚未在 2C 上架 | P0 |
| BR-06 | 列表需过滤 **2B 侧不可售/下架** 商品（与 App 一致） | P0 |
| BR-07 | 价格展示 = 2B **采购价**（单一价，**无阶梯价 / 会员价**） | P0 |

#### A2. 发散点

| 发散点 | 类型 | 优先级 | 说明 |
|--------|------|--------|------|
| 商品卡片：主图、标题、采购价 BDT、已发布标签 | 必备 | P0 | 与 App 卡片信息对齐 |
| Tab 切换保留搜索词 | 体验 | P0 | 切换 Tab 不丢 `q` |
| 空状态：无商品 / Tab 无数据 | 必备 | P0 | 引导切换 Tab 或联系运营 |
| 排序：综合、价格、上新 | 体验 | P1 | App 若有则对齐 |
| 类目筛选 | 体验 | P1 | 左侧栏或顶部筛选 |
| 无限滚动 vs 分页 | 体验 | P0 | Seller 后台建议 **分页**（便于对账） |
| 列表快捷「立即购买」 | 增值 | P2 | 本期可仅详情页购买 |
| 批量铺货 | 增值 | P2 | 非本期 |

#### A3. 页面结构草案

```
[页头：选品中心]
[搜索框：搜索 2B 商品名称/编码]
[商品网格：卡片 × N]
[分页器]
[次级入口：侧栏 Product Sourcing > Purchase Orders List]
```

#### A4. 铺货状态 Tab 定义（已确认，**仅 Purchase Orders List**）

| Tab | 判定逻辑 | 备注 |
|-----|---------|------|
| 全部 | 全部采购订单 | 仅 List 页 |
| 已发布 | 订单关联 **SPU** 已在 2C 店铺铺货上架 | **SPU 维度** |
| 未发布 | 订单关联 **SPU** 尚未在 2C 上架 | **SPU 维度** |

**粒度说明**：

- **采购**：按 **SKU** 选规格、数量下单；同一 SPU 下不同 SKU 可分别采购。
- **铺货**：按 **SPU** 一键上架；详情页展示 **SPU** 铺货状态（Published / Unpublished）。
- **Purchase Order Detail**：无铺货 Tab。

| 评价/营销 | 重 | 轻或不做 |

#### C2. 发散点

### 模块 D：立即购买 & 结算（银行转账）

**定位**：单笔下单闭环；支付 = 线下银行转账 + 平台/2B 确认。

#### D1. 立即购买弹层 / 中间页

| 发散点 | 类型 | 优先级 |
|--------|------|--------|
| 已选 SKU、单价、数量 | 必备 | P0 |
| 数量受 MOQ 约束；**允许超卖**（库存不足仍可下单） | 必备 | P0 |
| 小计预览 | 必备 | P0 |
| 确认 → 进入结算页 | 必备 | P0 |

#### D2. 结算页（Checkout）

**流程位置**：立即购买确认后 → **Checkout** → 点击 **Order & Pay** → 下单成功页。

**页面结构**：

```
[1] Shipping Address（地址：近期优先 / 店铺地址，可改选、新增、编辑、设默认）
[2] Product Information（图、标题、SKU、单价、数量、行小计）
[3] Shipping Method（Standard | Air Express | Air Priority）
[4] Payment Method（Bank Transfer，本期唯一）
[5] Order Summary（Subtotal、Shipping Fee、COD Handling Fee、Grand Total）
[6] Security Reminder（安全信息提醒）
[7] [ Order & Pay ]
```

| 区块 | 字段 / 选项 | 优先级 |
|------|------------|--------|
| Shipping Address | Recipient、Phone、行政区、Address、Change/Add/Edit/Default | P0 |
| Product Information | Image、Title、SKU Attributes、Unit Price、Quantity、Line Subtotal | P0 |
| Shipping Method | **Standard**（默认）、**Air Express**、**Air Priority**；切换重算运费与总价 | P0 |
| Payment Method | **Bank Transfer**（唯一，默认选中） | P0 |
| Order Summary | **Subtotal**、**Shipping Fee**、**COD Handling Fee**、**Grand Total** | P0 |
| Security Reminder | 转账至官方账户、金额一致、备注订单号、防诈骗提示 | P0 |
| 主按钮 | **Order & Pay** → 创建采购订单 | P0 |

**费用公式**：`Grand Total = Subtotal + Shipping Fee + COD Handling Fee`

#### D3. 下单成功页（Order Success）

**流程位置**：Order & Pay 成功 → **结算成功页**。

**页面结构**：

```
[Success Message] 成功话术 + 订单号 + Pending Payment
[Grand Total] 总价（与 Checkout 一致）
[Payment Details] 2B 固定账户、Amount to Pay、Copy
[Upload Payment Proof] 上传转账凭证
[View Order List] → Purchase Orders List
[Recommend] 推荐商品（You May Also Like）
```

| 区块 | 元素 | 优先级 |
|------|------|--------|
| Success Message | 图标、主标题、副文案、Order No.、Status | P0 |
| Grand Total | 总价 BDT；可选展开 Subtotal/Shipping/COD | P0 |
| Payment Details | Bank Name、Account Name、Account Number、Branch/SWIFT、Amount to Pay、Transfer Note、Copy | P0 |
| Upload Payment Proof | 与 App 对齐 | P0 |
| View Order List | 跳转 Purchase Orders List | P0 |
| Recommend | 推荐商品卡片，点击进入详情 | P0 |

#### D4. 银行转账业务规则（已确认）

| 规则 ID | 规则 |
|---------|------|
| PAY-01 | 提交订单后订单状态 = **待付款（待转账）** |
| PAY-02 | 收款账户为 **2B 店铺固定账户**（非每单动态生成） |
| PAY-03 | 商家线下转账至 2B 固定账户，并 **上传转账凭证** |
| PAY-04 | 2B 在 2B Web 根据 **订单号 + 转账金额** 确认收款 |
| PAY-05 | 确认收款后 → **待发货**；2C 端展示「已确认收款」 |
| PAY-06 | 金额不一致 / 多笔转账 → 2B 端人工处理（2C 展示处理中） |
| PAY-07 | **无待转账超时自动取消** |
| PAY-08 | BDT 格式、银行名称列表由 **后台配置** |

#### D5. 收货地址规则（已确认 BR-ADDR）

| 规则 | 说明 |
|------|------|
| 默认地址 | 优先 **近期收货地址**；若无则使用 **2C 店铺地址** |
| 地址操作 | 复用已有流程：编辑、添加、选择、设置默认地址 |

### 模块 E：采购订单

**定位**：2C 商家在选品场景下的 **采购单**（面向 2B），与消费者订单区分。

#### E1. 采购订单列表

| Tab 建议 | 说明 | 与 App 对齐 |
|---------|------|------------|
| 全部 | 所有采购单 | — |

## 五、订单状态机（跨端对齐）

```
                    ┌──────────────┐
                    │  提交订单     │
                    └──────┬───────┘
                           ▼
                    ┌──────────────┐
         ┌─────────│  待转账       │─────────┐
         │         └──────┬───────┘         │
    主动取消              │ 线下转账 + 上传凭证 │
         │                 ▼                 │
         │         ┌──────────────┐          │
         │         │ 待确认收款    │          │
         │         └──────┬───────┘          │
         │                 │ 2B 确认收款       │
         │                 ▼                 │
         │         ┌──────────────┐          │
         │         │  待发货       │          │
         │         └──────┬───────┘          │
         │                 │ 2B 发货          │
         │                 ▼                 │
         │         ┌──────────────┐          │
         │         │  待收货       │          │
         │         └──────┬───────┘          │
         │                 │ 签收              │
         │                 ▼                 │
         │         ┌──────────────┐          │
         └────────►│  已取消       │          │
                   └──────────────┘          │
                           │                 │
                           ▼                 │
                    ┌──────────────┐         │
                    │  已完成       │◄────────┘
                    └──────┬───────┘
                           │ 一键上架（须 2B 已确认收款）
                           ▼
                    ┌──────────────┐
                    │  SKU 已铺货   │（商品维度，按 SKU）
                    └──────────────┘
```

**已确认**：无待转账超时自动取消；一键上架 **严格依赖** 2B 确认收款。2C Web 状态名、颜色、可操作按钮需与 **App 采购订单** 一致；2B 确认收款是状态跃迁的权威来源。
