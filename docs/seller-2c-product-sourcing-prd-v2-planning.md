# Seller 2C — Product Sourcing V2 迭代规划

> **定位**：商家后台内 **2B 货源选品 / 采购** 模块（非独立商城）。  
> **基线**：`seller-2c-product-sourcing-prd-v1.0-final.md`（MVP v1.0）。  
> **用途**：产品勾选「采纳 / 不采纳 / 下期」后，再展开为完整 PRD v2.0。

---

## 一、V2 目标（建议）

在 MVP「能选、能买、能跟单、人工付款」基础上，提升：

1. **转化**：推荐、划线价/折扣感知。  
2. **效率**：购物车多 SKU、再次购买、搜索/导出。  
3. **协同**：关键节点邮件通知（2C 买家侧 + 2B/平台卖家侧）。  
4. **仍保持**：银行转账 + 客服联络为主，不做成独立 C 端商城。

### 2.1 你已提出的四项（建议作为 V2 主轴）

| # | 功能 | 简述 | 建议 | 采纳？ |
|---|------|------|------|--------|
| V2-01 | **商品推荐** | Discovery / Success / Detail 规则推荐（同类、热销、最近采购） | **P0** | ☐ |
| V2-02 | **购物车（Cart）** | 多 SKU 加购 → 合并 Checkout；与 Buy Now 并存 | **P0** | ☐ |
| V2-03 | **邮件通知** | 下单后、2B 确认收款后等节点；2C + 2B/配置邮箱 | **P0** | ☐ |
| V2-04 | **划线价 + 折扣 Tag** | 现价 vs 原价；列表/详情展示折扣（如 -20%） | **P0** | ☐ |

**V2-01 控范围建议**：不做全站算法；首版 **3 路规则** 即可：① 同店铺热销 ② 同类目 ③ 本店最近采购过的 SPU。

**V2-02 控范围建议**：Cart 仅本店铺、单 2B 货源；Checkout 可 **整单只读数量** 或 **仅在 Cart 改数量**（需二选一，见开放问题）。

**V2-03 控范围建议**：首版 **4 封邮件** 封顶：

| 触发 | 收件人（示例） |
|------|----------------|
| 采购单创建（Pending Payment） | 2C 店主邮箱 |
| 2B 确认收款 | 2C 店主 + 2B 联系人 |
| 订单发货（可选） | 2C 店主 |
| 订单取消 | 2C 店主 |

**V2-04 控范围建议**：字段 `originalPrice` + `salePrice`（或 discountRate）；无原价则不展示划线。

### 2.3 建议本期不做

| 功能 | 原因 |
|------|------|
| 多 2B 混合选品、阶梯价/会员价 | 战略级，非小迭代 |
| 待转账超时自动取消 | MVP 已明确不做 |
| 平台内在线支付 / 代收 | 与「联络客服转账」冲突 |
| 智能定价、自动补货、IM 机器人 | 复杂度高、运维重 |
| 与消费者 Orders 自动联动补货 | 跨模块，易膨胀 |

## 五、MVP v1.0 → V2 差异矩阵（摘要）

| 领域 | MVP v1.0 | V2（规划） |
|------|----------|------------|
| 下单路径 | 仅 Buy Now 单笔 | + Cart 多 SKU 合并下单 |
| Discovery | 列表 + Tab + 搜索 | + 推荐区、划线价/折扣 Tag、可选类目筛选 |
| Checkout | 单 SKU、Qty 只读 | 多行商品、费用规则需重新定义（是否仍仅 Subtotal） |
| Success | Contact Information | + 推荐；触发「下单邮件」 |
| 支付展示 | 不展示 2B 账户 | 维持；邮件可带联络指引，不带账户（除非业务变更） |
| PO | List/Detail、Cancel | + Buy Again、搜索、CSV；邮件在确认收款等节点 |
| 价格展示 | 单一采购价 | + 原价划线 + 折扣 Tag |
| 通知 | 无系统邮件 | 配置化邮件（2C/2B） |

## 七、依赖与风险

| 项 | 说明 |
|----|------|
| 原价/折扣数据 | 需 2B 或商品中台提供字段；无数据则 V2-04 降级为仅现价 |
| 邮件服务 | SMTP/第三方；模板英文化；失败重试与运营后台配置 |
| Cart 与库存 | 海外仓超卖规则是否延续到 Cart 汇总校验 |
| 合并下单 | 同一 Checkout 多 SKU 是否生成 **一单多行** 还是 **多单**（需交易中台确认） |
| 推荐数据源 | 热销统计口径（2B 店铺 / 本 2C 店） |

## 八、开放问题（定稿前请确认）

1. **购物车改数量**：仅 Cart 可改，还是 Checkout 也可改？  
2. **合并 Checkout**：一个采购单多 SKU 行，还是每 SKU 仍拆单？  
3. **邮件**：2B 收件人取店铺主邮箱还是固定运营邮箱？  
4. **折扣**：展示「-X%」还是「Save ৳X」或两者可配置？  
5. **推荐**：是否必须登录后才个性化（最近采购），未登录仅热销？  
6. **V2-12 凭证上传**：本期是否重新纳入？
